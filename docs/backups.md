# SIM 工作區備份、還原與接續

在左側「設定與資料」匯出完整工作區，或選擇已保存的 SIM JSON 還原。備份包含店務、行政、模擬金額與保留紀錄；行政的 CSV／列印只輸出所選範圍，完整還原請使用 JSON。

公開試用仍以每位訪客的 cookie 隔離資料，72 小時沒有活動後清除。自架資料保存在自己的實例目錄，沒有公開站的閒置清除期限；請定期把 JSON 下載到另一個保存位置。還原只影響目前訪客工作區，沒有團隊帳號或跨裝置同步。

## 匯出與確認還原

1. 按「匯出 SIM JSON」，下載 `freedom-erp-SIM.json`。檔案使用精簡 JSON，可另外保存日期版本。
2. 要還原時，按「匯入 SIM JSON」選檔。系統先解析 JSON、確認 SIM 標記並計算精簡內容大小，再顯示檔名、工作區、模組數與資料大小供核對。
3. 可先按「取消，保留現在資料」，下載目前備份。確認選對內容後，按「確認還原模擬資料」。完整資料檢查與提交通過後，才一次取代目前工作區。

預覽只顯示檔案摘要；全部欄位、引用、時段、SIM 守恆及容量驗證在伺服器提交前完成。成功還原會建立新的資料世代與工作區版本，瀏覽器不會把舊世代的教學進度或釘選混入新資料。

## 容量與驗證

| 項目 | 現行上限與處理方式 |
| --- | --- |
| 原選檔 | 最多 8 MiB（8,388,608 bytes）；原檔可能包含空白與縮排 |
| 傳輸內容 | JSON 解析後重新序列化的精簡 UTF-8 內容，最多 3 MiB（3,145,728 bytes） |
| 大檔分段 | 每段最多 24,000 bytes，再以 Base64 放入請求；每個完整請求本文仍不超過 32,768 bytes |
| 傳輸期限 | 從開始傳輸起 15 分鐘；接續或重試不延長原期限 |
| 工作區資料 | 原 JSON 字串長度 1,000,000、各集合數量、歷史與操作配額仍會驗證 |

MiB 是 1,048,576 bytes。傳輸以 UTF-8 bytes 計算，工作區的 JSON 字串長度是另一項限制；檔案大小合格，仍須通過資料結構與所有引用檢查。還原只接受 `simulation:true`、`real_finance:false`、`currency:'SIM'` 的模擬工作區，不會放寬銀行、正式金融、身份資訊或不允許欄位的拒絕條件。

較小內容直接使用原匯入流程；較大內容先傳暫存片段。分段還原會核對各片段長度與摘要、完整內容的 SHA-256、UTF-8 與 JSON 格式，再執行完整工作區驗證。摘要對應精簡後的傳輸內容，不能作為身份或簽核證明。收齊片段之前，原工作區不會被清空，也不會存入半份資料；驗證失敗時保留原資料。

## 取消、重選同檔與中斷處理

傳輸階段畫面會顯示已傳片段與進度，可按「取消傳輸，保留原資料」。取消會清除這次暫存傳輸；若取消結果尚未確認，先重新讀取，再從「設定與資料」按「取消未完成的備份傳輸」。取消預覽或傳輸都不會把備份內容寫入工作區。

完整檢查與提交開始後，畫面會改為等待原操作結果，這時不提供傳輸取消。請等結果確認，避免把「沒有收到回應」當成還原失敗。

網路中斷後，在開始後 15 分鐘內重選相同內容的 JSON，確認後會比對摘要、大小、分段數與原工作區版本，跳過已收到的片段。相同檔名但內容不同不會接續。若要換另一份備份，先取消未完成的傳輸；過期傳輸會清掉暫存片段，重新選檔後從頭傳送，原工作區保留。

操作頻率較密集時，畫面會顯示等待並接續同一份備份。若另一個視窗在傳輸期間修改了工作區，版本檢查會拒絕舊傳輸或提交；請重新讀取最新資料、取消舊傳輸，再核對要還原的內容。

## 提交後沒有收到回應

若畫面出現「上次操作的結果尚未確認」，按「確認原操作結果」。系統使用同一個操作代號、內容與原版本確認收據；已完成的還原會回覆原結果，不會再建立一次資料世代。

原操作暫存於此分頁的 sessionStorage；瀏覽器不能寫入時，會改存分頁記憶體並顯示提醒。看到記憶體暫存提醒時，先確認結果，再關閉或重新整理分頁。請勿先另送一份新還原來猜測結果。

## 自架儲存與舊資料

自架重新啟動會讀回已保存的資料與版本，不會重新加入範本或行政示範。較大的序列化狀態以摘要與多個片段，在同一次儲存交易中寫入，避免超過單一儲存值容量；片段缺漏或摘要不符時會拒絕讀取，不覆寫原資料。這項處理相容原先直接保存的 plain state。

舊 `freedom-administration-v1` 仍可缺少更正紀錄、出勤作廢旗標與公告封存旗標。讀取與還原驗證不會自動補寫行政預設值，後續成功執行行政命令時才加入。保留紀錄與前後快照仍須符合引用、時間、狀態及配額。
